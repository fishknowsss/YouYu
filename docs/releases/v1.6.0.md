# YouYu 1.6.0

YouYu 1.6.0 重新整理了专业模式设置页的诊断区域，并为后台通信和自动更新加入应用内连接保底。诊断日志现在默认导出到“下载”文件夹；后台与更新不再只依赖当前系统代理或单次系统 DNS 结果。

## 用户可见改进

- 设置页保留三行主要设置，将诊断日志独立为完整工具行；错误类型、日志条数和“导出”动作使用同一背景与统一对齐，不再像额外拼入一排开关。
- “导出”改为低权重动作，避免与“保存”“同步”“修复”争抢视觉重点。
- 保存诊断日志时默认打开当前 Windows 用户的“下载”文件夹，用户仍可选择其他目录。
- 常见错误继续以红色显示“问题类型 · 建议操作”；无错误时只显示可导出的日志条数，不增加说明性小字。
- 软件更新和诊断状态增加读屏播报；禁用按钮不显示可点击的悬停反馈。

设置页已在 `900×600` 下覆盖无异常、DNS 错误、长错误、0/200 条日志、导出中、检查失败和下载进度。三行主要操作保持 72px 节奏，诊断与更新区域左右边缘一致，页面没有横向或纵向滚动。

## 后台连接保底

使用登记、远程配置同步和流量上报现在通过 `youyu-api.fishknowsss.com` 访问 Cloudflare Worker。该入口是 Worker 的生产自定义域名，DNS 记录与证书由 Cloudflare 托管；旧 `workers.dev` 地址继续保留用于兼容和诊断。客户端通过一个不继承系统代理的 Electron 独立会话连接：

1. 先直接连接后台，避免系统代理或失效 Mihomo 成为单点故障。
2. 只有 DNS、拒绝连接、连接重置、超时、响应中断或临时网关状态等可恢复故障，才尝试正在运行的本地 Mihomo。
3. 401、403、429、HTTP 200 但内容无效、普通业务错误和用户主动取消不会换线路，避免把权限、限流或服务端数据问题误报为网络故障。
4. 直连和代理共享一次总超时，直连最多使用约 60% 预算，为第二条线路留出时间。
5. 两次尝试复用完全相同的请求体、报告 ID、设备种子、时间戳和签名，避免重复计量或身份漂移。

如果两条线路都失败，诊断只保留类似 `direct=ENOTFOUND proxy=ECONNREFUSED` 的脱敏结果，不包含后台 URL、订阅、用户身份、口令或请求体。

## GitHub 更新保底

三个更新通道改用 GitHub `releases/latest/download`：

| 通道 | 更新文件 |
| --- | --- |
| 标准版 | `latest.yml` |
| 内部更新通道版 | `latest-in.yml` |
| 无桌宠通道版 | `latest-no.yml` |

更新流程拆为两个独立阶段：

1. 检查通道元数据时先直连 GitHub；失败后清理应用内连接与 DNS 缓存，再按条件通过本地 Mihomo 重试。
2. 发现新版本后在后台下载安装包和 `.blockmap`。下载阶段重新从直连开始；如果 GitHub 资源 CDN 连接失败，同样可以换到本地 Mihomo，而不会只修复元数据检查。

下载仍在后台进行，设置页不会因为大文件下载一直处于全局操作锁定。差分下载不可用时会自动回退完整安装包，下载完成后继续执行哈希与签名校验。

## DNS 与安全边界

应用启用 Electron 内置解析器、Happy Eyeballs 和 secure DNS，并配置 DNSPod 的 `doh.pub`、阿里云的 `dns.alidns.com` 与 Cloudflare 的 `cloudflare-dns.com`、`1.1.1.1` 四个 DoH 入口。实机验证中，运营商 DNS 对新后台返回错误的 NXDOMAIN，而 secure DNS 能取得权威地址并完成正常 TLS 请求。这样可以在某个解析服务不可达、系统 DNS 被污染、缓存错误或 IPv4/IPv6 路径差异时提高连接成功率。

这些设置只作用于 YouYu 自身：

- 不修改 Windows DNS。
- 不写入 Hosts。
- 不固定 GitHub、Cloudflare 或资源 CDN 的 IP；这些地址会变化，固定后反而容易失效。
- 不关闭 TLS 证书校验，也不会因换线路接受错误证书。
- secure DNS 可能向 DNSPod、阿里云公共 DNS 或 Cloudflare DNS 发起解析请求；四个 DoH 都不可达时，后台与更新直连会失败并按条件尝试本地 Mihomo，不会回退到可能被污染的系统解析。

后台生产入口不再依赖 `workers.dev`，但自定义域名与旧入口仍指向同一 Cloudflare Worker，并不构成跨服务商镜像。因此这次改进是域名、解析与传输路径保底，不是绕过所有网络封锁：如果域名、SNI 或整个 Cloudflare 网络都被阻断，软件仍会明确报错，并可通过导出的诊断日志继续定位。

## 诊断导出

导出报告最多包含当前会话 200 条日志，并附带应用版本、构建通道、Windows 版本、运行状态和网络设置等必要环境信息。报告使用字段白名单并再次执行文本脱敏，不写入完整订阅、订阅地址、口令、设备密钥或后台凭据。

Node/Electron 产生的 `fetch failed` 现在会保留安全的嵌套错误码，例如 `ENOTFOUND`、`EAI_AGAIN` 或 `ECONNRESET`，因此常见问题分类可以更准确地区分 DNS、连接和后台故障。用户取消保存时不会创建文件。

## 保留的 1.5.11 修复能力

- 托盘只保留一个“网络修复”，完成重型清理后重启 YouYu，再由新进程启动新内核。
- 设置页“修复”不重启 YouYu；原本运行时使用新端口恢复 Mihomo，原本停止时保持停止。
- 修复会关闭并回读确认 WinINet 代理，清理代理字符串、WinHTTP、DNS 缓存和 Mihomo 易失缓存，并修复 Microsoft Store 回环豁免。
- 修复圆环保持可见旋转，并遵循 Windows 的“减少动态效果”设置。
- “已同步”“已保存”“已修复”只在设置页短暂显示，不进入首页诊断区域。
