# 官网交互展示方案

状态：已落地首轮实现。保持现有紫色、页面宽度、字体比例和信息顺序。

实现入口为 `site/`，使用 `npm run site:build` 更新 `docs/demo/`。首页点击“试用界面”加载真实组件演示；支持双模式、节点选择与测速、服务测试、TUN 演示和桌宠放出。网页桌宠支持拖动、下落、贴边、动作菜单及键盘收回。功能分层图位于双模式介绍区，按需展开。

## 推荐呈现

首屏仍是左侧介绍与下载、右侧软件预览。将右侧静态截图逐步替换为真实组件构成的演示窗口，窗口上方保留“小白模式 / 专业模式”。首次进入显示静态预览，点击“试用界面”才加载交互代码，避免影响首页加载。

在预览下方设置一块固定高度的功能说明，随当前操作更新。宽屏时可在窗口右侧放一条短引导，与下方说明配合；普通桌面和手机只显示下方说明，不挤压软件界面。不在窗口四周同时堆叠介绍气泡。

爆炸图放在首屏之后、双模式介绍附近，以“展开界面”按钮按需打开，内联显示在模式卡片上方。复用演示窗口的组件和素材；收起后释放空间，不新增独立的全屏版块。

```text
Landing Page（现有静态页面）
├─ Hero
│  ├─ 产品介绍、下载、版本信息（保留）
│  └─ ProductShowcase
│     ├─ 模式切换 / 试用界面
│     ├─ 静态截图 → 按需加载 DemoWindow
│     └─ FeatureDescription（当前操作对应的一条说明）
├─ 双模式介绍
│  └─ 展开界面 → ExplodedView（按需展开）
├─ 现有两列功能展示、下载、FAQ（保留）
└─ PetLayer（用户主动放出后，在网页内活动）
```

## 软件界面如何做到拟真

优先复用真实 React 组件、配色和素材，保留按钮状态、节点切换和反馈过程。演示窗口使用独立浏览器入口和内存状态，与 Electron 主进程分开。

现有可复用部分：

| 来源 | 用法与适配点 |
| --- | --- |
| `src/renderer/components/AppShell.tsx` | 侧栏和界面骨架；演示外层提供清楚可见的模式切换，保留应用内的原有操作方式 |
| `src/renderer/pages/Home.tsx` | 两种模式的真实首页；由演示控制器传入状态与回调 |
| `src/renderer/pages/NodeSelect.tsx` | 节点列表、选择、测速反馈，使用固定示例数据 |
| `src/renderer/pages/TestPage.tsx` | 连通性测试界面；当前直接使用 `window.youyu`，需要演示专用接口 |
| `src/renderer/devApi.ts` | 已有内存 API 和 README 演示数据可供复用；现有自动安装入口只在 `DEV` 生效，不能直接当作官网生产入口 |
| `src/renderer/components/PetSprite.tsx`、`src/renderer/pet/atlas.ts` | 真实桌宠帧序列、24 种状态与两张 WebP 图集 |

不直接启动完整的 `App.tsx`、`useAppController` 或 `PetApp.tsx`：前两者承担登记、远程配置和应用生命周期，后者依赖桌面窗口位置及鼠标穿透接口。官网采用小型演示控制器，只实现展示中的操作，不改变桌面客户端行为。

演示使用独立 iframe 隔离应用样式，入口静态构建到 `docs/demo/`，沿用 GitHub Pages。通过固定事件类型向父页面报告当前场景；父页面核对来源窗口和 origin，再切换说明或放出桌宠。页面通过 `ResizeObserver` 同步演示尺寸，桌宠和说明始终由父页面绘制。iframe 只获得脚本运行所需的能力，不开放顶层导航、下载或弹窗。

桌面尽量保留原窗口比例；手机进入演示后采用任务聚焦布局，每次展示启停或节点等一个操作区域，保留软件的视觉样式和至少 44px 的触控目标。为演示入口添加局部适配，不把整个桌面界面等比压缩成难以点击的小按钮。

| 用户操作 | 窗口中的反馈 | 窗口旁或下方的介绍 |
| --- | --- | --- |
| 小白模式连接 / 停止 | 短暂启动状态，随后更新连接状态 | “日常启停，在这里完成。” |
| 切换专业模式 | 展示真实首页和侧栏 | “需要调整时，节点、规则和流量都在这里。” |
| 选择节点 | 当前节点同步到首页 | “可以手动选择，也可以使用自动选择。” |
| 点击测速 | 有限时长的检测过程，展示预设结果 | “先看延迟，再决定使用哪个节点。” |
| 查看测试 | 显示逐项完成的演示结果 | “遇到连接问题，可以按服务查看结果。” |
| 切换规则 / TUN | 更新演示设置和对应状态 | 简短说明该选项的实际作用 |
| 放出桌宠 | 桌宠从预览区域走入网页 | “拖动它试试，也可以让它回到窗口。” |

窗口持续显示“交互演示”，首次操作旁说明“使用示例数据，不会修改系统网络”。连接、延迟、出口和流量均为固定演示数据；订阅输入、登记、更新安装、日志导出等真实系统操作不在演示中执行，也不收集真实订阅。

## 桌宠可以怎样互动

保留目前的挥手、走动、睡觉预览，增加“放出桌宠”。桌宠进入网页最上层的独立容器，可从演示窗口拖到网页空白处；不会覆盖导航和下载按钮，关闭或“回到窗口”后恢复原位。

- 使用真实主图集和补充图集，复用帧序列配置。
- 鼠标或触屏拖动：提起、拖动、释放、下落恢复；靠近网页边缘时贴边、探头、眨眼或休息。
- 点击挥手；动作菜单提供跳跃、睡觉和回到窗口。键盘可聚焦桌宠，使用方向键移动、Enter 挥手、Escape 回到窗口。
- 拖动使用 Pointer Events 与 pointer capture，只在桌宠上限制触摸滚动。处理拖动取消、屏幕旋转及窗口缩放，始终保留可操作的回收入口。
- 每帧只更新位置 transform；空闲、离屏及页面隐藏时停止计时。开启减少动态效果时取消自动走动和下落位移，保留手动操作与静态姿态反馈。

网页中的桌宠活动范围是浏览器页面。安装版负责跨软件窗口的桌面活动、屏幕贴边及系统托盘；这部分在官网用一句功能介绍和真实素材说明。

## 爆炸图怎样融入

以真实专业模式的界面构成分层，呈现“同一个客户端，按需要展开”：窗口底板、导航、节点与代理控制、流量与诊断、独立桌宠。这里的层次表示功能分组，不表示软件运行架构。

点击“展开界面”后，功能区内的分层预览轻微倾斜并错开各层，旁边出现对应名称和一句作用说明；悬停、点击或键盘聚焦某层时突出它。点击“收起界面”恢复平面并折叠预览，避免自动循环或强制滚动。桌宠作为独立角色出现在窗口边缘，可继续拖动。

实现采用真实界面图层配合 CSS transform，不引入 Three.js、WebGL 或动画框架。展开约 450ms，层间交错控制在 40ms 左右。手机纵向排列分层图和说明，减少动态效果时直接切换静态层次。

## 分步落地

1. 先完成双模式首页、节点选择及关联说明。点击进入才加载；加载失败保留现有截图和下载入口。使用专用演示构建配置，不改桌面应用入口。
2. 再实现网页桌宠的放出、拖动、贴边、动作菜单与回收；确认触屏操作及键盘路径。
3. 最后加入展开界面视图，以已完成的真实组件为素材。确认它能帮助理解产品后再保留入口。

验收围绕这些实际路径：连接与停止、模式切换、节点状态同步、说明同步、桌宠拖出及回收、爆炸图展开及复原。检查桌面、短屏、手机、减少动态效果、禁用 JavaScript 和加载失败场景；保持现有版本同步、下载地址及 Pages 部署方式。先测量首屏请求和交互帧表现，再决定是否需要进一步优化，不新增通用测试或 CI 流程。
