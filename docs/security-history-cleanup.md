# Git 历史与敏感内容治理

本文件记录 YouYu 仓库处理历史敏感内容的原则、执行边界和 1.5.9 的净化结果。历史改写会改变所有受影响提交和标签的对象 ID，只能在仓库所有者明确授权、影响面确认和离线备份完成后执行。

## 1.5.9 净化范围

历史审计发现并移除以下不应进入 Git 的内容：

- `cloudflare/youyu-traffic/.wrangler/`：Wrangler 本地状态、D1 SQLite 数据库和缓存；
- `release/` 与 `release-archive/`：历史安装包、内部构建和更新产物；
- `resources/generated/`：打包期间生成的订阅输入；
- `scripts/__pycache__/` 与 `*.pyc`：Python 字节码缓存；
- `resources/default-subscription.in.txt`：私有订阅的防御性清理路径，即使审计时未发现已提交对象。

处置前确认：仓库没有 fork 和历史 Pull Request；历史安装包内的旧订阅值已经失效，且与当前本地私有订阅不同；历史 Wrangler 本地设备身份与生产 D1 没有匹配项。因此无需破坏性重置当前生产后台凭据、现有设备或当前私有订阅。

## 执行流程

1. 暂停会被旧标签触发的发布工作流，并确认工作区已经提交。
2. 在仓库外创建包含全部分支和标签的离线 `git bundle`，记录 SHA-256，限制访问并设定删除时间。
3. 从本地已提交仓库创建新的镜像仓库，使用 `git-filter-repo` 的敏感数据模式按完整路径净化历史。
4. 审计所有重写后的分支、标签、对象路径和大对象，确认私有订阅、Wrangler 状态、发布产物和缓存均不存在。
5. 强制推送净化后的 `main` 与旧标签；重新启用发布工作流后，单独创建并显式推送当前版本标签。
6. 从远端重新抓取并核对提交、标签和 Release，再运行仓库卫生检查。
7. 如需删除 GitHub 缓存视图或只读 Pull Request 引用，向 GitHub Support 提供仓库、受影响 PR 数量和 `git-filter-repo` 输出的 First Changed Commit。

## 凭据处置原则

- 一旦确认仍有效的订阅、令牌、密钥或口令曾公开，先撤销或轮换，再改写历史。
- 历史值已经失效且与当前值不同，并不等于可以保留历史文件；仍应净化本地数据库、构建产物和缓存。
- 不因“可能泄露”而盲目重置没有泄露证据的生产密钥，避免使客户端、设备或管理后台无故失效。
- 离线备份本身仍包含旧历史，必须存放在仓库外、限制访问，并在确认远端净化稳定后删除。

## 防回归

- `.gitignore` 覆盖本地工具状态、环境变量、私有订阅、构建产物、归档、缓存和生成目录。
- `npm run validate:repo` 检查被跟踪路径、私有订阅、生成目录和常见敏感模式；CI 在 `main` 与 Pull Request 上执行同一校验。
- 公共发布必须使用 `npm run dist:win:release`，三个通道全部执行空内置订阅校验。
- 新增密钥只允许通过 Cloudflare Secret、GitHub Secret 或本地忽略文件提供，不得写入源代码、脚本参数、提交说明或 Release 文本。
