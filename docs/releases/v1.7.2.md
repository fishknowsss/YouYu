# YouYu 1.7.2 迭代说明

YouYu 1.7.2 聚焦于一次真实更新失败的根因：已安装的 `1.7.0` 能下载新版，却可能在点击“安装”后因为跨 UAC 的环境变量没有被带到安装器而直接退出。本版将这条链路改为可验证的受控交接，同时收紧 Codex 长连接恢复与后台更新界面。

## 自动更新安装交接

- 新客户端不再把安装交给默认的退出时自动行为。它先建立一份只在短时间内有效、绑定当前 Windows 用户 SID、会话、目标安装路径和 nonce 的交接记录，再通过受控提权启动器把四个必需参数显式传给 NSIS 安装器。
- 启动器会验证下载的是绝对路径 `.exe`，验证参数数量与格式，并在安装器于交接开始前退出时把失败返回给应用；此时应用不会把“已开始安装”误认为成功，用户仍可重试。
- 为兼容已经发布的 `1.7.0`，三个公开更新元数据均要求管理员权限。旧版 updater 经由确定的提权路径启动新安装器；新安装器只在当前用户、当前交互会话的规范 `LocalAppData\Temp` 中寻找一份新鲜、文件所有者匹配、目标程序精确匹配的交接记录。找不到或任意一项校验失败都会拒绝更新，不会回退到宽松路径。
- 交接记录只会在安装文件写入成功后被原子消费；失败、过期或取消时不会被普通安装误用。

这意味着当前仍在 `1.7.0` 的安装可在发布 `1.7.2` 后重新点击“检查”，下载到 `1.7.2` 后再点击“安装”。如果系统显示 UAC 提示，必须选择当前 Windows 用户对应的管理员授权；取消授权会安全地保留可重试状态。

## Codex 重连稳定化

日志显示的问题不是 YouYu 改写了 Codex 的代理选择，而是 Codex 到 ChatGPT 边缘的响应 WebSocket 偶发停在连接建立阶段。1.7.2 采用三层、彼此约束的处理：

1. `openai.com`、`chatgpt.com`、`oaistatic.com` 与 `oaiusercontent.com` 走规则感知的公共 DoH，仍由当前用户选择的代理组负责出口；
2. Mihomo 保持 TCP keep-alive，减少空闲长连接被中间链路静默回收；
3. 仅当连接同时满足 `codex.exe`、OpenAI 域名、TCP、已建立足够时间且连续快照没有收到响应数据等严格条件时，才关闭那一条连接并刷新 DNS 缓存。首次发现后会在连接实际建立约 8 秒处进行一次精确复查，避免依赖五秒流量轮询的偶然时序。

它不会调用“切换节点”“重新选择代理组”或“关闭全部连接”，因此不会改变你的手动节点、自动选择逻辑或其他应用的正常连接。

## 更新与后台界面

- 设置页和小白模式都会在用户手动检查时立即给出旋转反馈。旋转标识位于操作按钮的紧左侧，不再贴在整块更新组件最左边。
- 后台将稳定用户 ID 保留为内部主键，但不再在列表和资料编辑面板展示一长串无业务意义的随机值。
- 定向通知编辑器删除与下方操作重复的启用/停用选择，只保留“级别”和以 5 分钟为步进的“持续时间”；原有停止通知动作仍用于清除已下发通知。

## 验证范围

- TypeScript、桌面端与 Worker 测试、静态检查、格式检查、生产构建；
- 真实 electron-builder NSIS 编译与隔离静默安装器冒烟：显式 CLI、继承环境、旧版兼容恢复、正常新装、失败边界与交接消费顺序；
- 三个公开通道均检查安装包、更新元数据和 `isAdminRightsRequired`；私有 Team Build 与公开更新包继续使用各自独立的订阅交付边界；
- Codex 连接恢复的进程/域名/协议/时序筛选、精确关闭、DNS 刷新、冷却与生命周期停止覆盖。
