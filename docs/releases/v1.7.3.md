# YouYu 1.7.3 迭代说明

YouYu 1.7.3 将自动节点选择统一为可由后台管理的地区优先策略。默认优先日本，但不会因日本节点暂时不可用而中断工作；系统会切换到其他健康低延迟节点，并明确说明回退地区。

## 自动选择逻辑

自动模式按以下顺序执行：

1. 过滤订阅提示、官网、流量信息等不可选条目；
2. 对候选节点分别探测 Google 与 Cloudflare 的轻量端点；
3. 优先保留目标地区内双探测成功的节点，再按延迟排序；
4. 切换候选节点后，通过当前 Mihomo 代理请求 Cloudflare trace，核对实际出口国家代码；
5. 目标地区没有可用节点且允许回退时，从其他地区按同样的健康度和延迟顺序选择，并提示“目标地区节点均不可用，已自动切换至某地区节点”。

这套逻辑用于小白模式启动、应用启动后的自动策略、专业模式手动切回“自动”、订阅更新后重选，以及当前节点连续健康检查失败后的恢复。专业模式的手动节点仍由用户控制，不会因后台策略被静默改成自动。

## 后台全局与逐用户策略

后台“全局配置”新增：

- 优先地区：日本、香港、台湾、新加坡、美国、韩国、最低延迟；
- 地区不可用：自动切换、保持地区。

全局默认是“日本 + 自动切换”。用户管理的“客户端配置”使用相同字段，可选择跟随全局或单独覆盖。选择“最低延迟”时地区限制没有意义，因此不可用处理会自动禁用并按全局节点池选择。

“保持地区”用于不能接受跨区的特定账号：目标地区没有通过健康和出口校验的节点时不会选其他地区。“自动切换”适合日常生产：优先目标地区，但保持连接连续性并给出回退提示。

## 升级与兼容

- D1 迁移为既有全局配置补充 `preferred_region = 'jp'` 与 `region_fallback = 'global'`，逐用户旧配置继续继承全局。
- 客户端即使仍持有不含新字段的旧缓存，也采用日本优先和健康回退默认值；下一次认证配置同步会取得后台的显式策略。
- 更新安装不会覆盖用户的手动/自动选择。原来处于自动模式的用户在下一次启动、订阅刷新或健康恢复时应用新策略；原来处于手动模式的用户在小白模式启动或专业模式选择“自动”后应用。
- 规则来源、DNS、TUN、Steam/AI 规则、订阅地址、手动节点与公开/私有安装包边界均保持原有行为。

## 验证范围

- TypeScript、桌面端 92 个测试文件、Worker 75 项测试、ESLint、Prettier、仓库卫生与 Worker 生产 dry-run；
- 日本/香港/台湾/新加坡/美国/韩国名称识别，健康优先、延迟排序、候选出口拒绝、严格地区与跨区回退；
- 全局和逐用户 API 校验、空值继承、用户配置合并、旧数据库列修复与迁移幂等；
- 后台全局配置、用户抽屉及 `390×844` 窄屏实际浏览器渲染，控制台无错误。
